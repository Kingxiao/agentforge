# Prompt Cache 实战指南

> 来源：Claude Code src/services/api/claude.ts 的缓存实现

## 原理

Anthropic API 对连续相同的 system prompt 前缀做服务端缓存。

| TTL 选项 | 写入成本 | 读取成本 | 适用场景 |
|---------|---------|---------|---------|
| 5 分钟（默认） | 正常 ×1.25 | 正常 ×0.1 | 会话内复用，知识库短期稳定 |
| 1 小时（`"ttl": "1h"`，2025 新增） | 正常 ×2.0 | 正常 ×0.1 | 跨请求复用，超大型系统 prompt |

- **最大 breakpoint 数**：4 个（每条消息）
- **最小 token 阈值**：Opus 4096 / Sonnet 2048 / 其他 1024（低于阈值不缓存）
- **工作区隔离**：不同 API Key 缓存不共享（2026-02-05 起强制）

```json
// 默认 5 分钟 TTL
{"type": "ephemeral"}

// 1 小时 TTL（适合大型知识库、长期稳定的系统 prompt）
{"type": "ephemeral", "ttl": "1h"}
```

> verified: 2026-04-08（Anthropic 官方文档 + SDK changelog）

## 静态/动态分离架构 [CC]

```
System Prompt 布局：

┌──────────────────────────────┐
│  [STATIC ZONE]               │ ← cache_control: "ephemeral"
│  • 身份指令                   │
│  • 行为规则                   │
│  • 工具定义（核心工具）        │
│  • CLAUDE.md 内容             │
│  • 编码约定                   │
├──────────────────────────────┤ ← SYSTEM_PROMPT_DYNAMIC_BOUNDARY
│  [DYNAMIC ZONE]              │ ← 不缓存，每轮重算
│  • Git 状态                   │
│  • MCP 工具列表（可变）       │
│  • 当前会话上下文             │
│  • 任务通知                   │
└──────────────────────────────┘
```

## 缓存破坏因素

以下操作会导致缓存 miss：
1. **MCP 服务器连接/断开** — 工具列表变化
2. **CLAUDE.md 修改** — 静态区内容变化
3. **模型切换** — 不同模型的缓存不共享
4. **工具启用/禁用** — 工具定义列表变化

Claude Code 有 `promptCacheBreakDetection` 专门检测这些情况 [CC]。

## 成本分析

假设系统提示 10,000 token（Sonnet 4.6 价格），50 轮对话：

| 场景 | 第 1 轮成本 | 后续每轮 | 50 轮总计 |
|------|-----------|---------|----------|
| 无缓存 | $0.030 | $0.030 | $1.500 |
| 5 分钟 TTL 缓存 | $0.0375 | $0.003 | $0.184 |
| 1 小时 TTL 缓存 | $0.060 | $0.003 | $0.207 |
| **5 分钟节省** | -25% | **90%** | **87.7%** |
| **1 小时节省** | -100% | **90%** | **86.2%** |

> 注：1 小时 TTL 写入成本更高（×2 vs ×1.25），但对于跨会话复用（每天多次请求同一大型系统 prompt）总体更划算。
